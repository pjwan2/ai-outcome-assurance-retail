# Evaluation

## Dataset

`backend/app/fixtures/eval_dataset.json`, generated by `backend/scripts/generate_eval_dataset.py`
(re-run the generator to regenerate; do not hand-edit the JSON). Dataset version: `eval-dataset-v1`.

- 28 total cases
- 24 `critical_positive` — a required escalation/review pathway must be found
- 4 `negative_control` — a resolved minor-fault case must NOT trigger review (safe `DENY`)

Risk slices covered (`app/release_gate.py::REQUIRED_RISK_SLICES`): missing evidence, wrong seller,
wrong order, wrong product, stale source, hash mismatch, fabricated locator, source version mismatch,
source not allowed, contradiction, prompt injection, unsafe authority request (major failure confirmed
still requires human sign-off).

Sources pool: `backend/app/fixtures/eval_sources.json` — includes deliberately bad fixtures (stale
date, tampered hash, empty locator, wrong version, unallowed class, injected text, contradictory fault
assessments).

## Runner

`backend/app/evaluation.py::run_evaluation` runs every case through the same
`app.services.workflow.run_case_pipeline` used by the API and demo — no separate "eval-only" logic.
Metrics: critical recall, Wilson 95% lower bound on critical recall, false-authorisation count,
wrong-entity-evidence-admitted count, prompt-injection-altered-decision count, per-slice pass rates.

**RAG guardrail metrics** (`app/retrieval.py`, `app/guardrails.py` — see
[ADR 0006](adrs/0006-rag-guardrails-are-non-authoritative.md)), computed the same
no-hard-coded-numbers way:

- `mean_retrieval_relevance` — the average TF-IDF cosine relevance score across every case's
  retrieved candidates.
- `groundedness_pass_rate` — the fraction of cases whose generated case summary has zero ungrounded
  sentences. Currently 1.0 by construction: the generator only ever cites the `Claim` it was built
  from (see the ADR for what this number does and does not prove).
- `pii_redaction_count` — total PII findings (email/AU-mobile/credit-card pattern matches) across the
  dataset's case text and evidence excerpts; 0 on the current fixtures, which contain no PII by
  design.

## Actually reproducing this

```bash
cd backend
python -c "from app.evaluation import run_evaluation; import json; print(json.dumps(run_evaluation(), indent=2, default=str)[:2000])"
python -m pytest -q tests/test_evaluation_and_release_gate.py -v
```

## Observed results (this repository, this dataset version)

R1 (current fixtures): **24/24 critical positives recovered**, critical recall 1.0, Wilson 95% lower
bound ≈ **0.862** (see `docs/release_gate.md` — 24/24 observed is not a guarantee of future
performance, especially at this sample size).

R2 (regression fixture — see below): critical recall unchanged at 1.0 in this repository's current
implementation, but the gate still **BLOCK**s because it detects `WRONG_ENTITY_EVIDENCE_ADMITTED`
directly (see `docs/release_gate.md`). This differs from the PRD's illustrative "12/24" example —
that number was not reproduced here and is not claimed. Actual numbers are computed at
`make eval` / `pytest tests/test_evaluation_and_release_gate.py`, not hard-coded.
